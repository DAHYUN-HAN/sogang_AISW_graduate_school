# 관리자 게시판 웹 화면 — 2026-10-07

WP8/WP9 P0. 승인된 흰색 관리자 화면과 현재 회원 메뉴를 기준으로 실제
`/admin/boards` 화면을 구현했다. 웹 전용 표현을 바꿨으며 Expo Router,
관리자 보호 레이아웃, 기존 API/편집 처리기와 네이티브 화면을 유지한다.

## 구현

- 왼쪽 분류: 원우회 → 참여활동 → 커뮤니티 → 공지사항. 게시판 찾기는 없다.
- 오른쪽: 현재 자료공유/참여활동/공지 태그, 게시글 검색·상태 필터,
  10건 페이지 표와 상세·수정·고정·대표 이미지·삭제 작업.
- 소개·FAQ·회계장부·상조회·건의사항·일정의 기존 전용 관리 기능을 유지한다.
  이전 게시판은 접힌 추가 관리 항목, 미분류 게시판은 기타 게시판에서 연다.
  공지의 실제 게시판과 사용자 생성 하위 게시판은 세부 게시판 설정에서 연다.
- 새 게시판은 큰 분류·세부 위치·상위 게시판을 선택한다. 상위 게시판 안에
  하위 게시판을 만들고, 그 아래에도 다시 하위 게시판을 만들 수 있다.
- 삭제는 해당 게시판과 하위 게시판 전체를 숨긴다. 글·댓글·미디어를 보존하며
  숨긴 게시판에서 개별 복원한다. 상위 게시판부터 복원해야 한다.
- 운영 설정과 공지 편집은 필요할 때만 연다. 미저장 새 게시판·공지·운영 설정은
  이동/닫기 확인을 제공하며 진행 중 저장/조회는 메뉴 전환을 잠근다.
- 계좌는 관리자 권한의 기존 게시글 상세에서 확인할 수 있다. 일반 게시글 표에
  비공개 증빙을 노출하지 않는다. 건의사항 작성자는 익명으로 표시한다.

## 결정 기록

Ruling: 삭제는 복원 가능한 숨김으로 구현한다 — 기존 데이터 보존 요청을 따른다 —
영구 삭제가 필요하면 별도 정책과 기능을 추가해야 한다.

Ruling: 복원은 상위 게시판부터 개별 처리한다 — 원래 따로 숨겼던 하위 게시판을
뜻하지 않게 다시 노출하지 않는다 — 여러 하위 게시판을 복원할 때 작업이 늘어난다.

Ruling: 새 소개/FAQ 세부 게시판은 일반 게시판 유형을 기본으로 만든다 — 기존
전용 소개/FAQ 편집기는 고정 콘텐츠를 대상으로 한다 — 세부 게시판에도 같은
전용 편집이 필요하면 해당 편집기의 대상 구조를 확장해야 한다.

Ruling: 현재 승인된 로컬 브랜치와 작업 파일을 유지한다 — 이미 진행 중인 관리자
개편을 이어서 수정한다 — 병합/배포와 PostgreSQL 런타임 검증은 별도 작업이다.

  거절, 기존 비활성 설정의 하위 전파, 잘못된 분류 타입, SQL 분류/페이지 처리.

  복원 시 자식은 숨김을 유지했다. 검증 후 두 테스트 게시판은 숨김 상태로 남겼다.

  분류가 로드되는 것을 확인했다. 공지/운영 설정의 미저장 이동 확인도 확인하고
  임시 초안을 버렸다. 기존 공지와 설정은 저장하지 않았다.

## 최종 리뷰 처리

새 컨텍스트의 독립 리뷰를 한 차례 수행했다. 공지 수정 대상 전환 중 조회 취소,
설정 닫기 후 콘텐츠 쿼리 비활성, 실제 공지 게시판/하위 게시판의 관리 접근,
소개·FAQ 하위 게시판 생성 기본값을 수정했다. 마지막 행 삭제 후 페이지 범위를
벗어나는 문제도 사용자 영향에 따라 중요로 판정하고 보정했다. 대상 일치와
생성 기본값·페이지 보정은 실패→통과 회귀 테스트로, 화면 전환과 접근은 실제
브라우저로 확인했으며 이후 전체 테스트가 통과했다. 보류한 리뷰 항목은 없다.

추가 스키마 변경과 새 마이그레이션은 없다. 이번 구현은 선택적 기존 board
metadata에 관리 위치를 기록하며 회원 화면의 고정 메뉴를 자동 추가하지 않는다.
PostgreSQL/Docker 검증은 이전의 Docker Desktop Linux 엔진 파이프 부재로
`blocked`; 이 변경의 SQL/API 검증은 격리 SQLite에서 수행했다. iOS/Android
런타임은 기존 `Phase 5 QA` 범위다. 배포/커밋은 수행하지 않았다.

## 게시판 내부 테마 후속 정리

사용자의 후속 요청에 따라 웹 게시판 안의 소분류·상태 필터를 흰색 탭과 파란
선택 밑줄로 통일했다. 내부 섹션 제목은 메인처럼 15px/600, 입력·작업 버튼은
13px 기준으로 맞췄다. 소개/임원 편집, 공지, FAQ, 상조회·건의사항 목록과 운영
설정에 같은 여백·구분선·상태 색상을 적용했다. 고정 정책의 파란 배경 박스는
흰색 행과 얇은 구분선으로 바꿨으며 모든 필드·고정 정책·처리기는 유지한다.

`AdminBoardTheme.tsx`의 provider는 웹 게시판 작업 영역에만 적용한다. 다른
관리자 페이지와 네이티브 화면의 공통 컨트롤은 기존 표시를 사용한다. API·DB·
경로 변경과 새 기능은 없다. 기존 UI 테스트의 환경 구성에 테마 의존성의 기본
표시를 주입했다. 표시 변경을 복제하는 새 테스트는 추가하지 않았다.

- 최종 프론트엔드 전체 842/842, typecheck, 변경 파일 ESLint 통과.
- 실제 Expo + 격리 FastAPI 브라우저에서 자료공유의 시험족보, 스터디의 모집,
  행사공지 소분류 선택을 확인했다.
- 시험족보 운영 설정의 이름/설명/권한/고정 정책/저장/삭제, 소개 사진·임원 편집,
  FAQ 등록·수정·숨김, 건의사항 필터·답변, 공지 분류·이미지·원우회 연동·등록을
  확인했다. 저장/삭제/업로드는 실행하지 않아 기존 데이터는 변경하지 않았다.

  `board-theme-settings.png`. 테스트 로그: `board-theme-frontend-tests.log`.
