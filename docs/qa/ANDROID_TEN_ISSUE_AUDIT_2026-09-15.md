# Android 보고 이슈 10건 점검 — 2026-09-15

후속 업데이트: 사용자의 APK 빌드/실행 요청으로 APK 10을 만들고 10개 재현 절차를 수행했다. 최신 실행 결과와 추가 발견 사항은 [APK_TEN_ISSUES_2026-09-15.md](APK_TEN_ISSUES_2026-09-15.md)를 참고한다. 아래 내용은 그 이전 코드 및 APK 9 포함 여부 점검 기록이다.

WP5/WP9 P0 사용성 점검. 요청 범위는 현재 버전의 수정 반영 여부 확인이다.

## 결론

- 현재 작업 폴더에는 10건 모두 관련 기능 수정이 있다. 다만 9번은 요청한 **반투명 흰색**과 달리 **불투명 흰색 `#FFFFFF`**으로 구현되어 있어 요청 사양과 완전히 일치하지 않는다.
- 가장 최근 로컬 APK `AI-SW-CAMPUS-0.1.0-9-post-scroll.apk`에는 **4·8·9·10번 수정이 미반영**이다. 나머지 6건은 해당 수정 코드/네이티브 설정이 포함되어 있다.
- 사용자의 휴대폰에 설치된 APK 파일명/버전 코드는 확인되지 않았다. 아래 APK 판정은 로컬 버전 코드 9에 한정한다.
- 현재 코드의 전체 프런트엔드 테스트 **624/624 통과**, TypeScript 검사 통과. 오늘 `adb devices -l`에는 연결된 기기가 없었다. 이번 점검에서 새 Android 실행 검증을 수행하지 않았으므로 코드 포함 여부를 실기기 통과로 해석하지 않는다.

## 핵심 확인 결과

### 모집 글과 공지 로딩

실제 소스의 식/함수를 추출해 같은 입력으로 실행했다. Android 화면을 렌더링하는 테스트는 아니다.

- 동아리 안내, 이미지 2장: APK의 `hasVisualHero=false`, 별도 상단 이미지 영역 없음. 현재 코드는 별도 영역에 사진 2장을 생성한다. 실제 JSX 배치에서도 그 영역은 제목 다음, 본문 이전이다.
- 자동 재조회: APK의 새로고침 표시 판단은 `true`, 현재는 `false`.
- 사용자 당겨 새로고침: 현재도 `true`로 유지된다.
- 긴 글 `FormTextInput` 함수는 APK 9와 현재가 동일하다. 화면 파일 전체 해시가 다른 것은 달력 선택 표시의 반지름 변경 때문이며, 본문 스크롤 수정이 사라진 것이 아니다.

### 현재 코드와 커밋의 차이

`frontend/app.json`, `frontend/android/app/src/main/AndroidManifest.xml`, release manifest 검사 스크립트의 Back 호환 수정은 점검 시작 시부터 미커밋 상태였다. 해당 설정이 포함된 APK 9와 달리 **현재 HEAD 커밋만 가져와 빌드하면 같은 Back 수정이 포함된다고 보장할 수 없다.** 관련 회귀 테스트 두 파일도 점검 시작 시 untracked 상태였다. 기존 사용자 작업을 변경하지 않았다.
