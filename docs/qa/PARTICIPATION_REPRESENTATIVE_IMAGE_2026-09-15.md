# 모집 상세에 목록 대표 이미지가 함께 표시되는 원인

WP5/WP9, 사용자 첨부 SG_LLM 화면에 대한 원인 점검. 앱 코드와 운영 데이터는 변경하지 않았다.

## 결론

동아리·네트워킹 모집 상세가 **목록용 대표 이미지까지 상세 이미지에 포함해 표시하는 회귀**다. 저장/편집은 첫 이미지를 대표 이미지로 구분하지만 상세 렌더링에서는 그 구분을 사용하지 않는다.

첨부 화면의 첫 가로 포스터는 첫 번째 이미지이며 목록 대표 이미지로도 쓰인다. 다음 세로 포스터는 추가 상세 이미지다. 현재 상세는 두 장을 모두 제목 아래, 텍스트 본문 위에 표시한다. 텍스트 본문에 이미지를 삽입한 것이 아니라 별도의 이미지 영역이 전체 첨부 이미지를 그린다.

## 확인 근거

1. `frontend/app/(tabs)/board/post/create.tsx:1702`, `edit/[postId].tsx:525`는 대표 이미지에 **“목록 썸네일에만 사용합니다”**라고 명시한다. 별도로 상세 글 이미지 입력이 있다.
2. `frontend/utils/postAttachments.ts:24`의 `participationGuideImageSections`는 첫 이미지를 `representativeImage`, 나머지를 `detailImages`로 분리한다. 작성·수정 화면은 이 함수를 사용한다.
3. 목록 API `backend/app/routers/posts.py:447`의 `_post_attachment_subqueries`는 첨부 정렬 순서상 첫 이미지를 `thumbnail_media_id`/`thumbnail_url`로 반환한다. 목록 카드 `frontend/app/(tabs)/board/[boardId].tsx:882`는 이 썸네일을 표시한다.
4. 반면 상세 `frontend/app/(tabs)/board/post/[postId].tsx:471`은 전체 이미지 첨부를 모으고, `:684`의 `participationImagesSection`에서 **전체 배열을 map**한다. `:840`에서 제목 다음에 렌더링한다.
5. 대표 이미지를 제외하는 기존 함수 `participationGuideDetailAttachments`는 남아 있지만 현재 상세 화면에서는 호출하지 않는다.

## 변경 경위

- `95007d9` (2026-09-12): 사진 순서를 수정하면서 동아리·네트워킹 대표 이미지를 상세 상단에도 표시하도록 변경했다.
- `a8ff2d1` (2026-09-13): 모든 이미지를 제목과 본문 사이에 나열하도록 바꾸고, 상세 화면에서 대표 제외 함수 import/호출을 제거했다.
- 기존의 **대표 이미지는 목록 전용**이라는 작성·수정 규칙과 상세 화면이 불일치하게 됐다. APK 10에도 이 코드가 들어 있다.

## 영향 범위와 검증

현재 화면의 실제 TypeScript/JSX 선언을 추출해 가상 첨부 `대표 + 상세 + PDF`로 실행했다. 네이티브를 새로 실행한 검사가 아니라 현재 소스의 데이터 선택 및 렌더링 대상 확인이다.

| 화면 | 같은 이미지 영역 적용 | 현재 표시 |
| --- | --- | --- |
| 동아리 안내 `club-promo` | 적용 | 대표 + 상세 |
| 네트워킹 안내 `networking-programs` | 적용 | 대표 + 상세 |
| 스터디 모집 `study-recruit` | 미적용 | 별도 일반 첨부 경로 |
| 동아리 활동 인증 `club-activity` | 미적용 | 별도 활동 갤러리 경로 |

대표/상세 분리 함수는 같은 입력에서 상세 이미지만 정확히 골랐다. 기존 첨부 함수 테스트 7/7도 통과했다. 함수만 검사하므로 실제 상세 화면에서 호출이 제거된 문제를 잡지 못한다.

증거: `outputs/qa/participation-representative-audit-2026-09-15/`의 `probe.cjs`, `result.json`, `existing-helper-tests.log`. 화면 근거는 사용자 첨부와 앞선 APK 10의 `47-sg-llm.png`다.

## 수정 방향 — Phase 5 QA / P2

- 동아리·네트워킹 상세 이미지 영역에는 `detailImages`만 넘긴다. 목록 대표 이미지와 저장된 첨부는 유지한다.
- 앞서 요청한 **제목 → 상세 사진 → 내용 → 가입 신청** 순서는 유지한다.
- 대표만 있는 글에는 상세 이미지 영역을 만들지 않는다. 여러 상세 이미지와 PDF의 순서는 보존한다.
- 작성·수정 화면의 상세 이미지 안내는 아직 “본문 아래”라고 되어 있어, 위 요청 순서에 맞춰 문구도 정합성을 맞춰야 한다.
- 회귀 검사는 분리 함수뿐 아니라 실제 상세 화면이 대표를 제외하는지 확인해야 한다.
