# AI·SW CAMPUS 웹 전용 관리자 콘솔 설계

작성일: 2026-10-07 · 작업 범위: WP8 관리자 / WP9 통합

상태: **확정한 메인과 모든 기존 관리자 탭의 웹 페이지 구현.** 2026-10-07 사용자가 메인 구현 후 나머지 기능도 탭별 페이지로 구현하도록 요청했고, 미정인 사항은 임시 기본값으로 진행하도록 승인했다. 방향은 **관리자 웹 운영, 현재 기능 보존, PC 화면 전체 활용**이다. 메인 검증은 `docs/qa/ADMIN_MAIN_WEB_2026-10-07.md`, 전체 페이지의 기본값·기능 보존·검증은 `docs/qa/ADMIN_PAGES_DECISIONS_2026-10-07.md`에 기록한다.

현재 구현 결정: 메인 숫자 클릭은 날짜별 통계·게시글/댓글 목록·7일 추이를 갖춘 대시보드를 연다. 트래픽은 회원 전용 정책에 맞춰 로그인한 일반 회원의 앱/웹 이용만 수집하며 관리자와 비회원은 제외한다. 아래 시안의 익명 클라이언트 수집·로그인 병합은 구현하지 않는다. 웹에서 관리자 게시글 상세·작성·수정도 관리자 주소 안에서 이어지며, 기존 네이티브 관리자 진입과 기능은 호환성을 위해 보존한다.

## 1. 목표와 완료 기준

관리자가 PC 브라우저에서 게시판, 콘텐츠, 회원, 명부, 회비와 운영 설정을 관리한다. 검색 결과를 보면서 대상의 내용을 확인하고 수정할 수 있고, 작업 후에도 같은 검색 조건과 목록 위치에서 다음 대상을 처리한다.

- 관리자 영역은 브라우저의 가용 폭을 사용한다. 사용자 앱의 `405px` 모바일 프레임을 상속하지 않는다.
- 현재 8개 주요 메뉴와 게시판 유형별 관리 작업을 모두 제공한다.
- 관리자 화면과 운영 전용 조작은 웹에서 제공한다. 관리자 계정은 네이티브 앱에서 일반 회원 기능을 계속 사용할 수 있다.
- 로그인, 권한 검사, 비공개 미디어 접근, 명부/회비 처리와 저장 규칙은 기존 API를 따른다.
- 개별 관리 작업의 성공/실패를 확인할 수 있고, 미저장 입력이 탐색으로 사라지지 않는다.
- 1440×900, 1920×1080 PC 화면과 1024×768 작은 노트북 화면에서 필수 관리 작업을 수행할 수 있다.

이번 작업은 기존 P0 운영 기능을 웹에 재배치하는 WP8/WP9 작업이다. 2026-10-07 추가 요청에 따라 관리자 메인의 상조회/건의사항 접수 내역과 대시보드의 접속 트래픽, 어제/오늘 게시글·댓글 집계를 설계 범위에 포함한다. 고급 필터, 일괄 삭제, 외부 분석 서비스, 고급 분석과 회원 앱 전체 웹 재설계는 포함하지 않는다.

## 2. 현재 구조와 선택한 접근

확인한 근거:

- `frontend/app/_layout.tsx`: 웹의 `webAppShell.maxWidth`가 `405`이며 관리자도 같은 프레임 안에 표시된다.
- `frontend/app/admin/index.tsx`: 8개 섹션을 한 화면의 상태로 전환하고, 대부분의 관리 기능을 세로 카드와 가로 메뉴로 표시한다.
- `frontend/components/admin/`: 게시판 탐색/설정, 저장 피드백, 명부/회비 컴포넌트가 이미 분리되어 있다.
- `frontend/services/api.ts`: 관리자 통계/기록, 사용자 관리, 게시판/콘텐츠와 명부/회비 클라이언트가 구현되어 있다.
- `docs/phase2/FRONTEND_ROUTE_SPEC.md`: `/admin`과 역할 기반 진입 계약이 있다.
- `docs/superpowers/specs/2026-08-21-admin-board-content-controls-design.md`: 게시판을 하나의 메뉴에서 관리하는 기존 통합 설계를 유지한다.

접근 비교:

| 접근 | 장점 | 비용/한계 | 판단 |
| --- | --- | --- | --- |
| 기존 Expo 프로젝트에 웹 전용 관리자 셸과 화면 구성 | API, 인증, 검증, 타입과 게시판 기능을 재사용하며 PC 관리 동선을 만들 수 있다 | 현재 큰 관리자 파일에서 상태와 기능을 단계적으로 추출해야 한다 | 채택 |
| 현재 화면의 폭과 배치만 조정 | 변경량이 가장 작다 | 세로 폼/카드와 페이지 상태 구조가 남아 관리 동선 개선이 제한된다 | 부분 적용에만 적합 |
| 별도 React 웹 프로젝트 | 관리 도구에 특화된 독립 구성 | 인증, 배포, 공통 로직과 변경 검증 범위가 늘어난다 | 이번 범위에서 제외 |

FastAPI, SQLAlchemy, PostgreSQL과 Expo Router를 유지한다. 관리자 셸 재배치에는 새 데이터 저장소나 인증 체계가 필요하지 않다. 추가 요청한 트래픽은 현재 수집하지 않으므로 기존 백엔드의 자체 수집/일별 집계를 별도 작업으로 설계하며, 저장 모델을 추가할 경우 Alembic과 DB 계약을 함께 갱신한다. 웹 전용 DOM 화면 구성은 필요에 따라 `.web.tsx` 컴포넌트에 두고 공통 API/도메인 로직과 분리한다.

## 3. 전체 화면 구조

```text
┌─────────────┬──────────────────────────────────────────────────┐
│ AI·SW       │ 경로 / 페이지 제목           사용자 앱 보기 · 계정 │
│ CAMPUS      ├──────────────────────────────────────────────────┤
│             │ 검색 · 지원되는 필터                 주 작업 버튼 │
│ 메인        ├──────────────────────────┬───────────────────────┤
│ 대시보드    │ 상조회/건의 접수 또는     │ 선택 항목              │
│ 배너        │ 접속/작성 현황           │                       │
│ 게시판 관리 │ 목록 / 표 / 일정 목록    │ 상세 / 편집 / 미리보기 │
│ 계정        │                          │                       │
│ 원우 명부   │                          │ 저장 · 취소            │
│ 원우회비    │                          │                       │
│ 신고        ├──────────────────────────┴───────────────────────┤
│ 가입 설정   │ 전체 건수 / 페이지 이동                         │
│             │                                                  │

│ 이관 검수   │                                                  │
└─────────────┴──────────────────────────────────────────────────┘
```

### 공통 셸

- 왼쪽 메뉴: 폭 232px. 기존 `콘솔`을 접수 업무를 보는 `메인`과 이용 지표를 보는 `대시보드`로 분리한다. 나머지 7개 주요 메뉴와 운영 기록/이관 검수 진입은 유지한다.
- 운영 기록과 기존 데이터 이관 검수는 메뉴 아래 보조 진입점으로 제공한다. 기능을 복제하지 않는다.
- 상단: 높이 64px. 현재 경로, 로그인 관리자, 로그아웃, 사용자 앱 보기. 사용자 앱 보기는 별도 탭에서 열고 관리자 작업을 유지한다.
- 본문: 가용 폭을 사용하고, 좌우 여백 24px, 패널 간격 16px. PC 셸 전체에 `maxWidth: 405`나 다른 모바일 폭 상한을 적용하지 않는다.
- 목록: 열 제목 고정, 행 높이 기본 48px, 행 선택 상태 표시, 명시적인 열기/수정 버튼 제공.
- 오른쪽 상세 패널: 기본 400px, 넓은 화면은 최대 480px. 긴 본문·다중 이미지 편집은 본문 안의 넓은 편집 화면으로 전환한다.
- 등록/수정의 주요 버튼은 한 위치에 유지한다. 긴 폼은 하단 작업줄을 고정하며 저장 중 중복 요청을 막는다.

### 화면 폭별 동작

| 브라우저 폭 | 동작 |
| --- | --- |
| 1280px 이상 | 232px 메뉴 + 유동 목록 + 오른쪽 상세 패널. 필요한 표의 열을 넓게 표시 |
| 1024–1279px | 192px 메뉴. 기본 목록을 넓게 사용하고 상세는 오른쪽 겹침 패널로 열어 필수 열 폭 보존 |
| 768–1023px | 메뉴는 접을 수 있는 서랍. 상세는 본문을 대체하는 화면으로 표시 |
| 767px 이하 | PC 사용 권장 안내와 접힌 메뉴. 필수 조작은 제공하되 표 영역에만 가로 스크롤 허용 |

작은 브라우저 폭에서도 관리 셸을 의도적으로 405px에 고정하지 않는다. 긴 표의 가로 스크롤과 본문 세로 스크롤을 분리하며 전체 페이지 가로 스크롤은 피한다.

### 시각 규칙

- 2026-10-07 사용자 피드백을 반영하여 기존 메인, 공지 필터, 마이페이지/프로필과 선택 옵션 UI를 관리자 화면의 디자인 기준으로 삼는다.
- 기존 Pretendard 실제 폰트 자산과 브랜드 블루 `#2761FF`를 사용한다. 제목/섹션은 기존 앱의 500 중심 굵기를 따르고, 본문은 400을 사용한다.
- 전체 배경, 메뉴, 상단 바, 목록과 상세 편집 영역을 기존 앱의 흰색 `#FFFFFF`로 통일한다. 본문 `#15171C`, 보조 글 `#6B7280`, 구분선 `#E1E4E9`, 선택 배경 `#EDF2FE`를 기존 화면과 일치시킨다. 넓은 회색 배경과 통계/섹션을 둘러싼 카드 박스는 사용하지 않는다.
- 기존 홈/마이페이지처럼 여백과 얇은 구분선으로 섹션을 나눈다. 프로필 폼의 8px 입력/버튼 모서리와 44px 입력 높이, 선택 목록의 흰 표면을 활용한다. PC 표의 행/버튼 크기는 가독성과 작업 밀도에 맞춰 조정한다.
- 파랑은 선택/주 작업, 초록은 완료, 빨강은 실패/삭제에 사용한다. 상태는 색과 문자로 함께 표시한다.
- 메뉴/본문 기본 14px, 표 보조 정보 12–13px, 페이지 제목 22–24px를 기준으로 한다.
- 그룹 필터는 기존 공지/게시판처럼 둥근 칩과 검정 선택 배경/흰 글자를 사용한다. 내비게이션 선택은 앱 탭처럼 파란색으로 구분한다.
- 선택 옵션은 `SelectionSheet`와 프로필 선택 목록의 흰 표면, 행 구분선, 50px 행, 파란 선택 글자와 체크 표시를 재사용한다. PC에서는 입력 옆 팝오버로 배치하며 모바일 시트의 405px 폭을 복제하지 않는다.
- 큰 소개 카드와 반복 안내 문구는 줄이고 목록, 작업 버튼과 검증 메시지에 공간을 배정한다.

| 기존 UI 근거 | 관리자에 반영하는 요소 |
| --- | --- |
| `frontend/app/(tabs)/home.tsx` | 인사형 대시보드 헤더, 섹션 제목, 전체 흰 배경과 공통 색상 |
| `frontend/app/(tabs)/notices.tsx` / `board/[boardId].tsx` | 둥근 그룹 필터와 검정 선택 상태 |
| `frontend/components/MyPageDrawer.tsx` | 간결한 목록 메뉴, 본문/보조 글 색상, 얇은 구분선 |
| `frontend/app/(tabs)/settings/profile.tsx` | 라벨이 있는 폼, 44px 입력, 8px 모서리, 파란 저장 버튼 |
| `frontend/components/SelectionSheet.tsx` | 옵션 행/선택 체크/색상. 데스크톱 팝오버로 배치만 조정 |
| `frontend/components/AppTypography.tsx` / `utils/fontAssets.ts` | 실제 Pretendard 폰트와 굵기 대응 |

시안의 글꼴은 저장소의 실제 폰트 자산에서 필요한 글자를 추출해 포함한다. 제품 구현은 기존 루트 폰트 로딩과 `AppTypography`의 규칙을 재사용하며 별도 웹 폰트 제공자를 추가하지 않는다. 사용자의 흰색 기본 UI 요구에 따라 시안과 관리자 화면은 밝은 테마로 고정하며, 대화/브라우저가 어두운 테마여도 흰 표면과 기존 글자 색상을 유지한다. P2 다크 모드 도입은 이번 범위에 포함하지 않는다.

## 4. 메뉴별 화면과 기능 보존

### 메인: 상조회/건의사항 접수 업무

2026-10-07 사용자 확정: 최신 시안의 흰색 화면, 상단 통계 → 처리 대기 → 상조회/건의사항 내역 → 최근 운영 기록 순서와 아래 표시 조건을 메인 구현 기준으로 사용한다. 안내 문구 2개, 하단 빠른 작업과 이용 현황 보기 버튼을 제거한 상태까지 승인 범위에 포함한다.

로그인 후 기본 진입 화면이다. 기존 홈의 흰 배경과 인사형 제목 아래에 이용 통계, 처리 대기, 두 업무의 실제 접수 목록, 최근 운영 기록 순서로 배치한다. 접수 목록은 PC에서 나란히, 작은 폭에서 위아래로 배치한다.

- 처리 대기 위에 오늘 방문 수/방문자 수/페이지 조회 수, 어제/오늘 작성 게시글, 어제/오늘 작성 댓글을 모두 표시한다. 대시보드와 같은 데이터·날짜 경계를 사용한다. 숫자를 누르면 대시보드의 해당 지표/날짜 상세로 연결한다. 메인의 집계 시각 안내 문장은 사용자 요청으로 제거하고 집계 시각은 대시보드 상세에서 확인한다.
- 상단 요약: 상조회 처리 대기, 건의사항 답변 대기, 미처리 신고 건수.
- 상조회 신청 내역: 신청 제목, 신청자, 처리중/완료/반려 상태와 신청 확인. 미처리는 접수일시, 완료/반려는 처리일시를 표시한다. 증빙은 권한이 확인된 상세에서 조회한다.
- 건의사항 접수 내역: 제목, 기존 익명 표시 규칙에 따른 작성자, 접수/답변 완료 상태와 공식 답변 확인. 미처리는 접수일시, 답변 완료는 답변 처리일시를 표시한다. 기존 건의사항의 접수/답변 완료 상태를 보존하며 새로운 반려 상태는 추가하지 않는다.
- **미처리는 날짜와 관계없이 계속 노출한다.** 상조회 `processing`, 건의사항 `received`를 우선 표시하고, 완료/답변 완료/반려는 한국 시간 당일에 처리된 항목만 함께 표시한다. 당일 판단은 신청 생성일이 아니라 상조회 `reviewed_at`, 건의사항 `replied_at`을 사용한다. 처리 시각이 없는 완료 레코드를 생성일로 당일 처리로 추정하지 않는다.
- 서버가 전체 데이터에 `(미처리) OR (완료/반려 AND 당일 처리 시각)` 조건을 적용한 후 페이지네이션한다. 최근 접수 5건만 받아 필터링해 이전 미처리가 누락되는 방식은 사용하지 않는다. 미처리는 접수 최신순, 당일 처리는 처리 최신순이며 미처리 그룹을 먼저 표시한다. 표시 조건에 해당하는 항목이 많은 경우 페이지 이동/더 보기로 모두 접근할 수 있게 한다.
- 제목 옆에 미처리와 오늘 처리 건수를 표시한다. 각 수치는 서버가 계산한 조건별 전체 총계이며 현재 페이지 행 수로 대체하지 않는다. 과거 완료/반려 내역은 `전체 보기`의 기존 관리 목록에서 계속 조회한다. KST 자정/브라우저 재활성화 시 조건과 집계를 다시 조회하며 미처리 항목을 제거하지 않는다.
- 행을 누르면 해당 게시판과 항목의 상세/편집을 함께 연다. 답변/처리 상태 저장 성공 후 메인 목록과 대기 건수를 다시 조회하며, 실패 시 완료로 표시하지 않는다.
- 신청 목록 아래에 전체 폭의 최근 운영 기록 5건을 표시한다. 하단 빠른 작업 영역과 `이용 현황 보기` 버튼은 사용자 요청으로 제거한다. 통계 상세는 상단 지표 또는 왼쪽 대시보드 메뉴로 진입하며 각 관리 기능은 왼쪽 메뉴에 유지한다.
- `상조회 신청과 건의사항 접수 내역을 확인해 주세요.`와 `한국 시간 · 오늘 … / 어제 … 하루 전체` 안내 문장은 메인에서 제거한다.
- 일정 알림 생성과 푸시 전송 결과 확인은 운영 기록의 보조 작업에서 유지한다. 현재 푸시 비활성 결정을 바꾸지 않는다.

### 대시보드: 접속과 콘텐츠 작성 현황

- 상단에서 어제 작성 게시글, 오늘 작성 게시글, 어제 작성 댓글, 오늘 작성 댓글을 동시에 비교한다. 댓글은 답글을 포함한다.
- `오늘`은 한국 시간 00:00부터 마지막 집계 시각까지, `어제`는 전날 00:00부터 다음 날 00:00 직전까지다. 날짜와 오늘의 집계 시각을 표시하고 어제 하루 전체와 오늘 일부 시간을 동일 기간의 증감률로 표현하지 않는다.
- 게시글은 전체 게시판의 공개 완료된 글 중 삭제되지 않은 항목을 `created_at` 기준으로 집계한다. 건의사항/상조회 글도 포함하고 임시저장/숨김/삭제 글은 제외한다. 댓글/답글은 같은 기간에 생성되어 남아 있는 레코드를 집계한다. 삭제 후 값이 바뀔 수 있는 현재 상태 집계다.
- 접속 트래픽: 오늘 방문 수(세션), 방문자 수(중복 제거), 페이지 조회 수와 최근 7일 날짜별 추이를 제공한다. 지표를 누르면 해당 추이로 전환한다.
- 방문 수는 앱/웹의 이용 세션 수이며 30분 비활동 후 다시 이용하면 새 세션으로 계산한다. 방문자 수는 하루의 중복 제거된 계정 또는 익명 클라이언트 식별자 수로 정의하고, 익명 이용 중 로그인한 같은 클라이언트는 당일 중복 제거한다. 페이지 조회는 화면/라우트 진입이며 백그라운드 폴링, 같은 화면 재렌더와 관리자 콘솔 자체 이용은 제외한다. 익명 이용은 기기/브라우저가 달라지면 서로 다른 방문자로 계산될 수 있다.
- 아래의 오늘/어제 선택은 게시글과 댓글 목록을 함께 전환한다. 건수와 상세 목록은 같은 기간/필터를 사용하고, 게시글 선택은 해당 관리자 상세로 연결한다. 댓글 목록은 원글·작성자·댓글을 확인하고 기존 신고/관리 흐름으로 연결한다.
- 기존 전체 회원/게시글/댓글과 최근 30일 활성 회원, 공지/미처리 신고 지표는 보조 현황으로 유지한다. `users_active_30d`는 로그인한 회원 지표로, 방문자나 트래픽을 대신하지 않는다.

현재 `GET /admin/stats`와 `AdminStats` 타입에는 누계와 최근 30일 로그인 회원만 있고 날짜별 작성 건수/트래픽은 없다. 날짜별 콘텐츠는 기존 생성 시각을 서버에서 KST 경계의 UTC 범위로 집계한다. 트래픽은 자체 수집과 일별 저장/조회 계약을 추가해야 한다. 신규 집계 API도 `require_admin`, 기존 `{status, data}` 형식과 기간별 목록 페이지네이션을 따른다. 외부 분석 제공자는 도입하지 않는다.

트래픽 수집 시작 이전 날짜와 수집 비활성/실패 상태는 `수집 시작 전`/`집계 불가`로 표시하며 `0회`로 대체하지 않는다. 수집 시작일과 마지막 집계 시각을 응답에 포함한다. 시안의 모든 접속 숫자는 가상 데이터다.

### 게시판 관리

기존 통합 게시판 관리의 `그룹 → 실제 게시판 → 콘텐츠/운영 설정` 구조를 유지한다.

- 상단 그룹: 전체 / 공지사항 / 커뮤니티·자료 / 참여활동 / 원우회.
- 실제 게시판은 서버의 분류와 정렬 정보를 사용한다. 게시판 선택과 새 게시판 등록을 제공한다.
- `전체 게시글`은 여러 게시판의 목록이다. 특정 게시판을 선택하지 않은 상태에서는 운영 설정을 표시하지 않는다.
- 기본 콘텐츠 화면은 검색, 기존 상태 필터, 총계, 목록과 페이지 이동이다.
- 게시글 표 기본 열: 제목 / 게시판 / 작성자 / 작성일 / 고정 여부 / 작업. 실제 응답에 없는 상태값이나 신규 필터는 만들지 않는다.
- 목록을 벗어나 사용자 앱의 405px 작성 화면으로 이동하지 않는다. 관리자 셸 안에서 전용 작성/수정 화면을 열고, 기존 입력 검증과 API를 재사용한다.
- 상세/편집을 닫으면 선택한 게시판, 검색어, 상태 필터, 페이지와 목록 스크롤을 복원한다.
- 운영 설정은 현재 지원되는 이름, 설명, 노출, 정렬, 익명/읽기/쓰기 권한과 게시판별 표시 설정을 편집한다. 기존 고정 정책은 변경할 수 없는 사유를 함께 표시한다.

| 콘텐츠 유형 | 웹 관리 화면 | 보존할 작업 |
| --- | --- | --- |
| 전체/일반/자료 게시글 | 표 + 상세/넓은 편집 화면 | 검색, 등록, 수정, 고정, 삭제, 첨부 |
| 공지 | 표 + 공지 편집 화면 | 분류, 이미지/첨부, 마감일, 고정, 활동내역 연동 |
| 사진첩 | 썸네일을 포함한 목록 + 갤러리 편집 | 사진과 글 관리 |
| 활동 인증 | 목록 + 승인된 상세/편집 | 활동일, 사진, 소감, 참여자, 계좌와 기존 접근 규칙 |
| 동아리/네트워킹 안내 | 목록 + 전용 글 편집 | 대표 사진, 안내, 신청 링크와 대표 이미지 교체 |
| 건의사항 | 접수/답변 필터 + 상세 | 공식 답변, 기존 접수/답변 상태 변경 |
| 상조회 | 처리 상태 목록 + 상세 | 비공개 증빙 확인, 완료/반려, 기존 삭제 조건 |
| 원우회 활동내역 | 연동 공지 목록 | 공지 기반 연동과 원본 편집. 별도 활동 데이터 생성 금지 |
| 일정 | 기존 일정 목록 + 날짜 선택 + 편집 | 분류, 제목, 시작/종료, 장소, 내용, 삭제 |
| 원우회/기장단/역대 원우회 소개 | 소개 카드 목록 + 넓은 편집 화면 | 인사말, 소개, 임원, 순서, 사진과 활동 기록 |
| FAQ | 정렬 순서 포함 표 + 편집 | 질문, 답변, 분류, 활성 상태, 이미지/첨부 |
| 외부 링크 | 링크 입력 + 현재 연결 정보 | 기존 HTTP(S) 링크 검증과 저장 |
| 가이드 | 설명 + 운영 설정 | 지원되는 게시판 메타데이터. 없는 글 작성 기능 생성 금지 |

### 배너

- 목록: 썸네일, 연결 대상, 정렬, 노출 여부, 시작/종료 시각.
- 편집: 모바일/태블릿/PC 이미지 업로드를 같은 화면에서 관리한다.
- 오른쪽 미리보기: 실제 앱과 같은 이미지 전용 배너 렌더링. 관리용 이름/설정값을 앱 이미지 위에 합성하지 않는다.
- 현재 링크 입력과 공지글 연결, 이미지별 교체, 기간, 순서, 노출 중지 작업을 보존한다.

### 계정

- 표: 이름, 기수, 이메일, 전공, 재학 상태, 권한, 계정 활성 상태. 열은 실제 사용자 응답 필드에 맞춘다.
- 기존 검색, 권한/활성 필터, 페이지 이동을 유지한다.
- 상세에서 권한, 활성 상태, 재학/휴학/졸업 상태를 변경한다. 역할 변경과 비활성화는 대상과 결과를 확인하는 기존 확인 절차를 유지한다.
- 회원 계정과 영구 원우 명부는 서로 다른 데이터다. 한 화면의 동일 사용자 레코드처럼 합치지 않는다.

### 원우 명부

- 표: 이름 / 학번 / 전공. 전체 건수, 검색과 페이지 이동 제공.
- 상단 주요 작업은 `명부 엑셀 업로드`이며 결과로 신규/갱신 건수와 검증 실패를 보여준다.
- 신규 학번 추가, 기존 학번의 이름/전공 갱신, 누락 원우 보존 규칙을 유지한다.
- 기존 API에 없는 개별 명부 수정, 행 삭제와 내보내기를 새로 만들지 않는다.

### 원우회비

- 표: 원우 신원 정보 / 현재 납부 범위 / 적용 활동인증 게시판 / 납부 설정.
- `현재 학기 전체 납부자 업로드`와 `개별 행사 1회 납부 등록`을 서로 구분해 표시한다.
- 개별 편집은 `ALL`, 지정한 한 활동인증 게시판의 `ONCE`, `UNPAID`를 유지한다. 이름/학번/전공은 읽기 전용이다.
- 납부자 엑셀 업로드는 이전 ALL/ONCE를 전부 교체하며 업로드된 원우를 ALL로 등록한다. 실행 전 파일과 교체 의미를 확인하고, 결과를 보여준다.
- 파일 검증 실패 시 전체 작업이 적용되지 않는 현재 동작을 유지한다. UI 미리보기를 실제 서버 검증 성공으로 표현하지 않는다.

### 신고

- 표: 대상 종류, 대상 내용/식별 정보, 신고 사유, 상태, 접수 시각.
- 오른쪽에서 대상 글/댓글과 신고 내용을 확인하고 접수/검토/해결/기각의 기존 상태를 변경한다.
- 신고 대상 삭제와 신고 상태 변경을 구분한다. 삭제 실패 시 해결 완료로 표시하지 않는다.
- 관리자 댓글 관리 등 현재 신고 흐름에 있는 작업을 보존한다.

### 가입 설정 / 운영 기록 / 이관 검수

- 가입 설정: 기존 전공 목록 추가, 이름/정렬/활성 편집과 개인정보처리방침 버전/적용 시각 설정을 표시한다. 별도 정책 본문 편집 기능을 만들지 않는다.
- 운영 기록: 기존 API의 작업, 관리자, 대상, 시각, 지원되는 필터와 페이지 이동을 제공한다. 메인은 최근 5건, 전체 화면은 서버 페이지네이션으로 조회한다. 대상 아래에 변경 내용 요약을 표시한다. 변경 가능한 로그 편집 UI를 만들지 않는다.
- 이관 검수: 기존 `/admin/migration-review` 진입을 유지하고 실패/보관/미매핑/이관 상태와 이관 원장을 웹 표로 표시한다. 원문 개인정보와 운영 비밀을 추가하지 않는다.

### 운영 기록의 생성 범위

사용자의 2026-10-07 요청에 따라 공지 작성과 관리자 계정이 수행한 운영 변경을 자동 기록한다. 단순 화면 열기/검색/통계 조회는 별도 운영 변경을 생성하지 않는다.

| 기능 | 기록할 작업 예시 |
| --- | --- |
| 공지/일반 게시글/소개 콘텐츠 | 작성, 수정, 삭제, 상단 고정/해제, 대표 이미지 변경 |
| 게시판/가이드/외부 링크 | 등록, 이름/설명/권한/노출/정렬/운영 설정과 연결 주소 변경 |
| 건의사항/상조회 | 공식 답변 저장, 접수/처리 상태 변경, 반려 처리 |
| 배너/일정/FAQ | 등록, 수정, 삭제 또는 비노출, 이미지/순서 변경, 일정 알림 실행 결과 |
| 계정/가입 설정 | 권한/활성/재학 상태 변경, 전공 선택지 저장, 정책 적용 정보 변경 |
| 원우 명부/원우회비 | 명부 추가/갱신 결과, 전체 납부자 교체 결과, 개별 ALL/ONCE/UNPAID 변경 |
| 신고/댓글 관리 | 신고 처리 상태 변경, 관리자에 의한 대상 글/댓글 삭제와 작성/수정 |

- 각 기록은 서버 시각, 서버 인증으로 확인한 관리자 식별자/표시명, 기능별 `action`, 대상 종류/ID와 안전한 변경 요약을 가진다. 예: `공지사항 작성 / 2학기 수강 안내 / 관리자 / 10월 7일 11:18`, `상조회 처리 / 신청 #41 / 처리중 → 완료`.
- 기존 `OperationalAuditLog`와 `log_admin_action`을 재사용하고, 업무 변경과 기록을 같은 DB 트랜잭션으로 저장한다. 성공한 변경만 메인에 표시한다. 실패/롤백/취소, 값이 같은 단순 저장은 완료 기록을 생성하지 않는다. 일정 알림처럼 실제 실행된 운영 명령은 생성 0건이어도 실행 결과를 남긴다.
- 클라이언트가 보내는 관리자 이름/성공 메시지로 기록을 만들지 않는다. 한 업무 변경당 기록 한 건을 생성하고, 프런트는 성공 후 운영 기록 캐시를 갱신한다. 같은 변경을 여러 하위 API가 나눠 처리하는 경우에도 사용자 업무 단위의 중복 기록을 방지한다.
- 삭제 후에도 대상을 이해할 수 있도록 허용된 제목/기능명 요약을 기존 `details`에 보존한다. 계좌, 비공개 증빙, 비밀번호/토큰과 신청/건의 본문은 변경 요약에 복사하지 않는다. 필요한 enum/권한/노출 상태의 전후 값만 표시한다.
- 현재 백엔드는 공지 생성, 글 삭제/고정, 게시판, 배너, 일정, FAQ, 명부/회비, 계정, 가입 설정, 건의/상조회와 신고 상태 변경의 일부 기록을 이미 제공한다. 일반 관리자 게시글 생성과 공통 글 수정, 관리자 댓글 관리 등 누락 경로를 실행 전에 API별로 대조해 보완해야 한다. 이번 시안에서 이를 모두 구현된 서버 기능으로 간주하지 않는다.

## 5. 라우트와 앱 진입

웹은 관리자 전용 로그인과 콘솔을 제공한다. 현재 학교 이메일 로그인/세션 API를 재사용하며 새로운 관리자 비밀번호나 인증 서버를 만들지 않는다.

| 제안 라우트 | 화면/조건 |
| --- | --- |
| `/admin/login` | 브라우저용 관리자 로그인. 로그인 뒤 서버에서 확인한 admin 역할로 진입 |
| `/admin` | 메인: 상조회 신청/건의사항 접수 내역 |
| `/admin/dashboard` | 접속 트래픽, 어제/오늘 게시글·댓글 현황 |
| `/admin/banners` | 배너 |
| `/admin/boards` | 전체 게시글/게시판 선택 |
| `/admin/boards/[boardId]` | 선택 게시판의 콘텐츠 |
| `/admin/boards/[boardId]/settings` | 해당 게시판 운영 설정 |
| `/admin/accounts` | 계정 |
| `/admin/roster` | 원우 명부 |
| `/admin/dues` | 원우회비 |
| `/admin/reports` | 신고 |
| `/admin/registration` | 가입 설정 |
| `/admin/audit-logs` | 운영 기록 |
| `/admin/migration-review` | 기존 이관 검수 |

- 검색어/필터/페이지/선택 대상은 페이지별 허용된 URL 쿼리로 표현한다. 주소 복사와 새로고침 뒤 같은 목록을 복원한다.
- 기존 `/admin?section=...`와 게시판/일정 바로가기 파라미터는 새 화면으로 변환한다. 기존 내비게이션 유틸리티의 지연 로딩/누락 게시판 처리도 유지한다.
- 반환 주소는 검증된 내부 `/admin` 경로만 허용한다. 로그인 후 허용되지 않은 외부 주소로 이동하지 않는다.
- 비로그인은 `/admin/login`, 일반 회원은 권한 안내와 사용자 앱 이동, 권한 회수/계정 비활성은 세션 재확인 후 관리자 데이터를 제거한다.
- 네이티브 앱의 관리자 메뉴와 운영 전용 패널은 제거하거나 `웹 관리자 열기` 진입으로 교체한다. `/admin` 딥링크는 관리 화면을 렌더링하지 않고 웹 안내/열기와 사용자 앱 복귀를 제공한다.
- 관리자 계정의 일반 회원 기능과 본인 작성 글 편집은 유지한다. 관리자 역할의 서버 권한을 기기 종류로 제한하지 않는다.
- 배포 시 주소는 기존 정식 도메인의 `/admin`을 사용한다. 앱의 외부 브라우저 진입은 기존 환경별 웹 주소 설정을 확인해 연결하고 IP/새 도메인을 하드코딩하지 않는다.

## 6. 컴포넌트와 데이터 경계

제안 구조:

```text
frontend/app/admin/
  _layout.tsx                 # 관리자 경로의 플랫폼 분기
  login.tsx                  # 공개 웹 로그인; 공통 인증 로직 재사용
  (console)/
    _layout.tsx              # 세션/역할 보호 + 웹 관리자 셸
    index.tsx                # 메인: 접수 업무
    dashboard.tsx            # 이용/작성 지표
    banners.tsx
    boards/...
    accounts.tsx
    roster.tsx
    dues.tsx
    reports.tsx
    registration.tsx
    audit-logs.tsx
    migration-review.tsx

frontend/components/admin/
  shell/                     # 사이드 메뉴, 상단, 반응형 패널
  lists/                     # 표, 검색/필터줄, 페이지 이동
  editors/                   # 게시판 유형별 기존 편집기 추출
  ...                        # 기존 명부/회비/저장/삭제 컴포넌트

frontend/hooks/admin/        # 페이지별 조회와 변경; 기존 도메인 유틸리티 사용
frontend/services/api.ts     # 기존 API 클라이언트와 타입
```

- 최상위 레이아웃의 사용자 앱 프레임 적용 여부를 라우트로 구분한다. 관리자 로그인까지 넓은 웹 레이아웃을 적용하고 회원 화면은 기존 프레임을 유지한다.
- 루트에 관리자 경로 자체를 등록하고, 하위 콘솔에서 역할을 보호한다. `/admin/login`을 admin 역할 보호 안에 넣어 비로그인 접근을 막지 않는다.
- 세션 하이드레이션 이전에 관리자 데이터를 요청하지 않는다. 프런트 역할 보호와 모든 기존 백엔드 `require_admin` 검사를 함께 유지한다.
- 현재 `userStore`, JWT/회전 refresh와 React Query의 사용자별 캐시 경계를 재사용한다. 별도 관리자 세션 저장소를 도입하지 않는다.
- 표/패널은 데이터 표현만 담당한다. 권한, 게시판별 검증, 변경 후 캐시 갱신은 공통 도메인 로직과 조회/변경 훅에 둔다.
- 현재 저장 조정과 삭제/저장 성공 피드백을 먼저 재사용하고, 화면 이동에 필요한 상태만 점진적으로 분리한다. 4,729줄 관리자 파일 전체를 한 번에 재작성하지 않는다.
- 기존 편집 API의 관리자/소유자 접근 규칙과 작성 시점 이름/기수 스냅샷을 보존한다.

## 7. 작업 중 상태와 오류

- 초기 로딩, 검색 결과 없음, API 실패를 구분한다. 실패한 데이터는 `0건`으로 표시하지 않고 다시 시도를 제공한다.
- 데이터 재조회가 미저장 폼 값을 덮어쓰지 않는다. 다른 대상/메뉴로 이동하거나 브라우저를 떠날 때 저장하지 않은 변경을 확인한다.
- 저장 성공 후 대상 목록과 관련 앱 캐시를 갱신하고 해당 항목 선택을 유지한다. 마지막 행 삭제는 기존 규칙대로 이전 페이지로 이동한다.
- 저장 실패 시 입력과 오류 메시지를 유지한다. 저장 중 연속 클릭, 이미지 교체와 대상 변경의 경합을 막는다.
- 증빙과 계좌 등 비공개 정보는 목록에서 불필요하게 전부 보여주지 않고 허용된 상세/편집 문맥에서 조회한다.
- 이미지와 파일은 기존 관리자 인증 후 발급하는 단기 URL을 사용한다. 직접 공개 `/uploads` 접근으로 바꾸지 않는다.
- 웹 업로드, 확인, 미리보기, 다운로드와 새 탭 열기는 브라우저에 맞는 동작으로 제공한다. 기존 native Alert에만 의존해 웹의 확인/결과가 보이지 않게 하지 않는다.
- 키보드로 메뉴/표/폼을 탐색할 수 있고, 상세 닫기는 포커스를 선택 행으로 돌린다. 모달은 포커스 이동, Escape 닫기와 접근 가능한 이름을 제공한다.
- 권한 상실, 요청 실패와 검증 실패는 서버 응답의 코드/메시지를 따른다. 서버 성공 전에 목록이나 납부 상태를 완료로 확정하지 않는다.

## 8. 구현 묶음과 검증

각 묶음은 WP8/WP9에 기록하고 실행 전 기존 API/권한/라우트 계약을 확인한다.

1. **웹 진입과 셸**: 관리자 로그인/역할 보호, 모바일 프레임 분리, 메뉴/라우트, 네이티브 웹 진입 처리.
2. **메인과 게시판 탐색**: 처리 대기 위의 이용 통계 요약, 상조회/건의 접수 목록과 정확한 상태별 총계, 최근 운영 기록, 게시판 선택과 콘텐츠/설정 탭, 구 주소 호환. 관리자 변경 경로별 기록 누락을 보완하고 같은 트랜잭션의 기록/캐시 갱신을 검증한다.
   **대시보드 지표 확장**: KST 날짜별 콘텐츠 집계/목록과 자체 접속 수집/일별 집계를 별도 수직 작업으로 구현한다. 현재 누계 API에 없는 지표를 UI 계산으로 대체하지 않는다. API/DB/권한 계약과 필요한 Alembic 변경을 먼저 기록한다.
3. **게시판 콘텐츠/편집**: 일반 글부터 공지, 건의/상조회, 일정, FAQ, 소개/외부 링크까지 유형별 수직 전환. 관리자 등록/수정이 좁은 회원 화면으로 빠져나가지 않게 검증.
4. **계정/명부/회비**: 표, 검색/페이지, 권한/활성 변경, XLSX 업로드, ONCE 편집과 원자적 실패 회귀 검증.
5. **배너/신고/가입 설정/이관 검수**: 남은 관리 기능과 보조 도구 이전, 전체 기능 대조.
6. **통합**: 웹 로그인/새로고침/직접 주소/세션 만료/권한 회수, 미디어/다운로드/업로드, API 권한과 네이티브 회원 앱 회귀 검증.

검증 기준:

- 기존 8개 메뉴의 모든 조작과 위 콘텐츠 유형 표를 실제 화면/지원 API에 대응시킨다.
- 프런트 typecheck/lint와 관련 회귀 테스트, 웹 export가 통과한다.
- API에서 비로그인/일반 회원의 관리자 작업 거부와 관리자 허용을 확인한다.
- 메인의 상태별 총계/최신 목록과 저장 후 재조회, 대시보드 집계/목록의 KST 자정 경계 및 답글 포함 여부를 검증한다. 트래픽의 세션 만료, 당일 중복 제거, 재렌더/폴링/관리자 이용 제외, 수집 전 날짜와 집계 실패 표시를 확인한다.
- 메인 통계가 처리 대기 위에 있고 대시보드와 일치하는지 확인한다. 관리자 공지 작성/수정/삭제, 공식 답변/상조회 처리와 설정/엑셀 작업의 운영 기록이 성공 후 한 번 생성되고 실패/취소/롤백 시 남지 않는지 API와 브라우저에서 검증한다.
- 오래된 건의/상조회 미처리의 유지, 완료/반려의 처리 시각 기준 KST 당일 필터, 자정 경계/날짜 변경/재활성화와 처리 시각 미상 레코드의 제외를 검증한다. 전체 관리 목록에서 과거 처리 건을 조회할 수 있고 삭제한 안내 문장/빠른 작업/이용 현황 버튼이 메인에 다시 나타나지 않는지 확인한다.
- 목록의 검색/페이지/선택/스크롤 유지, 미저장 확인과 저장 실패 재시도를 브라우저에서 확인한다.
- 1920/1440/1024 폭을 실제 브라우저에서 확인하고, 작은 폭에서는 접근 가능한 대체 배치를 확인한다.
- 명부 누락 원우 보존, 회비 전체 교체, ONCE 게시판 범위, 파일 오류 시 미적용을 회귀 검증한다.
- 네이티브에서 관리자 콘솔을 렌더링하지 않고 일반 회원 기능과 본인 글 관리가 유지됨을 확인한다.
- 로그인 이후 주소 새로고침이 호스팅에서 404가 되지 않도록 기존 웹 배포의 라우트 fallback/export 설정을 검증한다.
- Docker runtime smoke는 구현 통합 시 수행하고, 실행 불가 시 정확한 사유를 기록한다. 이 설계 작성만으로 통과를 주장하지 않는다.

## 9. 화면 시안과 이번 산출물의 한계

대화의 화면 시안은 가상 데이터로 메뉴, 표 검색, 목록 선택, 상세 편집과 회비 교체 확인 동선을 탐색하기 위한 것이다. 운영 API 호출이나 실제 저장/업로드/삭제를 수행하지 않는다.

시안 검증: 2026-10-07, 메인 표시 조건과 불필요한 안내/작업 영역 제거 후 headless Microsoft Edge에서 21개 점검을 통과했다. 오래된 미처리 유지, 처리 시각 기준 당일 완료/반려 표시, KST 자정 양쪽 경계와 처리 시각 미상 제외, 과거 처리 건의 전체 목록 접근을 확인했다. 미처리 행은 접수 시각, 당일 처리 행은 처리 시각을 표시하며 요청한 안내 문장/빠른 작업/이용 현황 버튼이 메인에 없음을 확인했다. 11개 메뉴 진입, 처리 대기 위 통계 배치와 해당 대시보드 상세 연결, 메인의 신청/건의 상세 진입과 저장 후 대기 건수/운영 기록 갱신, 오늘/어제 건수와 목록 일치, 댓글 전체 목록, 트래픽 3개 지표 전환, 검색/목록 편집, 미저장 이동 확인, 행 포커스 복원, 새 게시판 등록, 예시 회비 변경/전체 교체, 명부 누락 원우 보존, 실제 앱 폰트 로딩/본문 색상, 옵션 선택 체크와 Escape 닫기를 확인했다. 예시 공지 작성/수정/삭제가 각각 기록 한 건을 생성하고, 입력 검증 실패/삭제 취소는 기록을 남기지 않으며 메인 최근 기록은 5건으로 제한됨을 확인했다. 런타임 오류는 없었다. 밝은/어두운 호스트 테마 모두에서 11개 화면의 셸/메뉴/목록/표 머리글과 상세/옵션 표면이 흰색인지 확인했다. 1920/1440/1024/768/360/320px에서 메인/대시보드의 셸 가로 넘침과 그래프 폭을 검사하고 PC 화면과 선택 옵션의 스크린샷을 확인했다. 이는 가상 데이터 시안 검증이며 실제 트래픽 수집, 서버 기록의 트랜잭션/누락 보완, 인증/API, 제품 typecheck/export, 네이티브와 Docker 검증을 대체하지 않는다.

이번 산출물은 설계와 화면 검토용 시안이다. 제품 코드, DB, 배포와 앱 빌드는 변경하지 않았다. 구현 단계에서는 이 문서를 기준으로 `docs/phase2/FRONTEND_ROUTE_SPEC.md`의 현재 계약을 갱신하고, 기능별 구현/검증 결과를 `CODEX.md`에 기록한다.
